# Alpha implementation contract

The release is `0.1.0a1`, Python 3.12+, with PyTorch as the required runtime dependency. This development machine is Intel macOS, whose last available PyTorch wheel is 2.2.2. Use PyTorch >=2.2.2,<3 and NumPy <2 for that legacy wheel; keep AMP compatibility for both `torch.amp` and the older `torch.cuda.amp.GradScaler`. Do not claim the full dependency range has been validated. The original `plan.md` describes the full product. This alpha implements local single-device training and a real single-worker remote path. Distributed strategies, automatic cloud provisioning, automatic recovery, and remote inference must raise specific unsupported errors until implemented. Do not create success-shaped stubs.

## Module ownership

The orchestrator owns common errors, version, final integration, and smoke checks. Agents own separate modules: model/planning; data/transforms; checkpoint; training; remote artifacts/serialization; cluster; inference/recipes/providers; package/CLI/documentation. Preserve other agents' files. No commits or changes to the supplied plan are required.

## Shared interfaces

- `mlzo.errors` supplies `MLZOError`, `ConfigurationError`, `UnsupportedFeatureError`, `TrainingError`, `CheckpointError`, and `ClusterError`.
- `mlzo.model`: `Lazy(factory, *args, gpu=None, **kwargs)`, `materialize(module, device, seed=None) -> nn.Module`, `place(module, *, gpu=None, gpus=None)`, `FactoryRef.from_callable(value)`, `FactoryRef.resolve()`. FactoryRef has `module` and `qualname` fields and dict conversion. Lazy exposes `factory`, `args`, `kwargs`, and local `materialize(device=...)`. The model helper resolves nested Lazy nodes at canonical paths and preserves aliases.
- `mlzo.planning`: `plan_run(run, *, on=None, parallel='auto', example=None) -> Plan`. Run has `algorithm_input`, `data`, and `config` dict. Plan exposes `device`, `precision`, `explain()`, `to_dict()`. No model construction or batch consumption during planning. GPU placement metadata is validated. `pipeline(...)` returns a configuration that planning rejects clearly in this alpha.
- `mlzo.data`: `DataPipeline`, `data(source)`. Pipelines offer `build(epoch=0)`, `__iter__`, optional `__len__`, immutable chain operations, and `to_spec(encode)` / `from_spec(spec, decode)` for remote serialization. Build happens on the execution worker. In-memory/native datasets remain supported locally. A factory source is importable for remote runs.
- `mlzo.transforms`: thin PyTorch function transforms and `tensor` / `NamedTensor`.
- `mlzo.checkpoint`: `CheckpointPolicy(to, every=1000, keep_last=3, mode='full')`, `checkpoint(to, ...)`, `CheckpointRef` with `path`, `snapshot_id`, and dict conversion. `save_snapshot(state, *, to, run_id, metadata=None, keep_last=None) -> CheckpointRef`; `load_snapshot(reference) -> dict`; `list_snapshots(to)`. Save complete restricted tensor/primitive state with checksums and atomic manifest publication. `reference` may name a committed snapshot or a root with a latest pointer. Never load arbitrary pickle. Local storage is required; S3 is optional behind an extra. Unsupported per-block/distributed semantics fail clearly.
- `mlzo.training`: `Training`, `Step`, `Run`, `train`, `opt`, schedules, `History`, `RunStatus`. Run stores `algorithm_input`, `data`, `config`, `id`, and `_engine` once prepared. Configuration excludes fit budget. `train()` and `Run.plan()` do not construct lazy models or call training factories. `Run.fit` accepts total epochs OR iteration steps, optional cluster, parallel, code, resume, wait. `Run._remote_cluster` identifies an attached remote handle. Use the common engine on local and remote paths. `run.status()` returns a dataclass or dict with a state. Engine exposes `model`, `state_dict()`, and `load_state_dict()`; checkpoint module knows nothing of the engine. Engine handles checkpoint policy at safe boundaries. Preserve original model recipe for inference exports.
- `mlzo.cluster.Cluster.submit(run, *, epochs=None, steps=None, parallel='auto', code=None, resume=None) -> str` durably accepts a remote job and returns its run ID. `get_run(id) -> dict`, `events(id, after=0) -> list[dict]`, `wait(id) -> dict`, `cancel(id)`, `checkpoint_run(id, to=None)`, `export_run(id, to, block=None)` support Run delegation where implemented. Every unsupported operation raises explicitly. `cluster(name, *, endpoint=None, token=None, ...)` creates/loads cluster configuration. `run(id, on=cluster)` reconnects through a remote handle. Worker `join` and `serve` use the same cluster service as the CLI.
- Remote code serialization lives in `mlzo.cluster.artifacts` and `mlzo.cluster.serialization`. It accepts primitives, importable callable references, root Lazy, pipeline, optimizer/schedule/checkpoint specifications; rejects arbitrary pickle, closures, eager models and custom Training instances for remote submission. Zero-argument importable training factories are supported. `serialize_run(run) -> dict`, `deserialize_run(spec) -> Run`. `snapshot_project(path, ...)` / `extract_project(...)` produce and verify bounded immutable source archives. Exclude credentials, virtualenvs, datasets and outputs. Submitted code is trusted user code, not sandboxed. Dependencies are prepared in a worker job environment, never copied from macOS.
- Artifact details: `snapshot_project(path, *, destination=None, data_paths=(), max_bytes=104857600) -> ProjectArtifact`; fields `path`, `digest`, `size_bytes`, `manifest`, `data_mapping`. `data_mapping` maps declared absolute local data paths to archive-relative paths. `extract_project(archive, destination, *, digest=None, max_bytes=104857600) -> dict` validates before extraction and returns the manifest. `serialize_run(run, *, data_paths=None)` may rewrite data paths using this mapping; `deserialize_run(spec)` resolves relative data paths from the extracted project working directory. Archives expose declared project dependencies for worker-side installation. The cluster agent must inspect these modules' exact implementation before integration.
- Cluster alpha transport is bounded JSON over authenticated HTTPS, with HTTP allowed only on loopback for local development. A SQLite coordinator persists workers, one-use/expiring invitations, jobs and scalar events. Workers poll for assignments, launch the common training engine in an isolated subprocess, and spool results. This is a single-owner service, not a sandbox for hostile code or an HA scheduler. Client submission/admin credentials are distinct from worker enrollment/identity. Never run training in coordinator requests. No tensor relay. Avoid arbitrary object deserialization or shell string execution.
- `mlzo.inference`: `export_model(model, *, to, recipe=None, block=None) -> ArtifactRef`, `load_artifact(reference, *, device='cpu', factory=None) -> nn.Module`, `deploy(artifact, *, on=None, device=None, factory=None)`. A local deployment supports `predict`, `status`, and `shutdown`. A weights-only artifact without a recipe requires an explicit factory. No arbitrary object deserialization. Remote inference is deferred unless complete.
- Public entrypoint `mlzo.cli.main:main`, `python -m mlzo`. Top-level exports are integrated after modules exist. Do not replace package functions with submodule objects accidentally.

## Validation and limits

Initial alpha validation used compilation, imports, packaging, and tiny smoke checks. The subsequent readability review adds focused CPU regression checks to preserve the implemented contracts in `plan.md`. Run them with `.venv/bin/python -m unittest discover -s tests -v`; see `docs/readability-follow-up.md` for the checks and their limits. This is not a full CI, GPU, or numerical validation matrix. Use `.venv/bin/python` for repository checks. Do not modify the shared environment concurrently or install dependencies independently.

Use documented PyTorch APIs, retain original forward semantics, and report alpha limits honestly. Basic import must not initialize CUDA, contact a service, or require optional dependencies. The package build must not import torch. License selection and publication belong to the owner; do not invent a license or publish to PyPI.
