# MLZO documentation site

The reader site documents the implemented `0.1.0a1` Python alpha. It uses
[Astro Starlight](https://starlight.astro.build/), an MIT-licensed static
documentation framework. Search uses a built Pagefind index; fonts ship locally.
No hosted search account or paid documentation service is needed.

## Run locally

Use Node.js 24+ and Python 3.12. The site does not need PyTorch installed.
From this directory:

```sh
npm ci
npm run check:reference
npm run check
npm run build
npm run check:links
npm run preview
```

Open `http://localhost:4321/mlzo/`. Use `npm run dev` while editing. Search needs
the production build, so verify it with `npm run preview`.

Guides live in `src/content/docs`. The API and CLI pages are generated by
`npm run reference`, which reads Python AST signatures and the CLI parser
without importing MLZO. The generator checks all top-level `__all__` exports;
new exports need a reference entry and a useful description. Commit regenerated
reference pages with source changes. Check generated signatures against the
behavioral guide when changing a contract.

## GitHub Pages

The checked-in workflow validates PRs and deploys pushes to `main`. A manual
workflow dispatch can deploy another reviewed branch after the workflow exists
on the default branch. In repository Settings > Pages, select **GitHub Actions**
as the build source when using that workflow. The workflow does not merge code
or publish Python packages.

The default canonical origin is `https://zpy52.github.io`, with base `/mlzo`.
For another repository or domain, set `DOCS_SITE` and `DOCS_BASE` consistently
for build and link checks. For a root domain, use `DOCS_BASE=/`.

The initial review preview can also be published as the built static files on a
`gh-pages` branch with Pages' branch source. That branch contains generated
output only. To move to the included Actions workflow after merging, change
Pages' source to GitHub Actions. Keep that switch separate from content edits.

## Checks

`check:reference` detects stale generated pages and missing public exports.
`check` validates Astro/TypeScript. `build` generates the static site and search
index. `check:links` checks built page URLs, fragments, assets, and base-path
containment. The docs workflow also executes the ordered quickstart and custom
algorithm snippets using CPU PyTorch, so the first-run instructions remain
executable. These checks do not validate remote hosts, GPU training, or TLS.
