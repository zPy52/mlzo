<p class="intro">Describe a learning program in Python, inspect its plan, then run it on one local device or an enrolled remote worker. Keep your PyTorch models, losses, and optimizers.</p>

<div class="flow" aria-label="The MLZO workflow">
  Describe <span aria-hidden="true">→</span> Plan <span aria-hidden="true">→</span> Train <span aria-hidden="true">→</span> Checkpoint or export
</div>

```python title="Your first deferred run"
import mlzo
import torch
from torch import nn

inputs = torch.randn(64, 4)
targets = (inputs.sum(dim=1) > 0).long()
batches = mlzo.data(inputs, targets).batch(16)

run = mlzo.train(mlzo.Lazy(nn.Linear, 4, 2), batches,
                 loss="cross_entropy", seed=7)
print(run.plan(on="cpu").explain())
history = run.fit(epochs=2, on="cpu")
```

`Lazy` stores a construction recipe. `train()` records configuration, and `plan()` inspects it without building the model or reading batches. `fit()` constructs the model, binds the optimizer, and executes training.

## Read this as an alpha

This documentation describes the implemented `0.1.0a1` release. Training uses one device or one worker per run. Checkpoints and inference artifacts use local filesystems. Distributed training, managed provisioning, automatic recovery, and remote inference are future work.

Start with the [core concepts](./start/concepts/) or check the [support matrix](./help/support/) before choosing a deployment. The [release notes](./help/release/) explain what is available and how the current CPU tests exercise it.
